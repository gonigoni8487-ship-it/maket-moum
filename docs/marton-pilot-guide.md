# 마트ON 현장 시범운영 가이드

> 말하면 연결하고, 찍으면 알려주고, 요청하면 처리되는 매장 AI

이 문서는 마트ON을 한 매장에서 2~4주 시범운영할 때 필요한 준비, 사용법, 효과 측정 방법을 정리한 것입니다.

## 1. 무엇이 바뀌나

| 지금 | 마트ON |
| --- | --- |
| 무전·전화·직접 찾아가서 요청 | 부서 지정 요청 → 해당 부서 휴대폰에 즉시 알림, 처리자·시각 기록 |
| 긴급 상황 전달 누락 | 긴급은 사이렌 + 누군가 확인할 때까지 1분 간격 재알림 |
| "OO 어디 있어요?" 매번 부서에 문의 | 상품 찾기·음성 질문으로 위치 즉시 안내 |
| 가격표 오류를 눈으로 대조 | 가격표 촬영 → 시스템 가격과 비교 → 오류 요청 원터치 |
| 도난·손실을 감으로 판단 | 상황·위치·시간·상품 기록 → 다발 구역·시간대 분석, 순찰 추천, 주간 리포트 |
| 구두 인수인계 | 퇴근 시 미처리 업무 자동 요약 + 메모 → 다음 근무자 확인 |

## 2. 준비물

- 서버 1대 (사내 서버 또는 클라우드, Node.js 20 이상). HTTPS 주소 필수(푸시 알림·카메라·마이크 요구사항)
- 직원 휴대폰 (안드로이드 Chrome 권장, 아이폰은 iOS 16.4 이상 + 홈 화면 추가)
- 선택: Gemini API 키(사진 AI·AI 답변), EAS 게이트·CCTV 분석기 웹훅 연동

## 3. 서버 설정

```bash
npm ci
npm run build
npm start          # http://0.0.0.0:3000 → 앞단 HTTPS 프록시 연결
```

| 환경변수 | 필수 | 설명 |
| --- | --- | --- |
| `MARTON_MANAGER_PIN` | 운영 필수 | 점장/부점장 로그인 PIN. 6자리 이상 권장 |
| `MARTON_STORE_CODE` | 권장 | 매장 공용 접속 코드. 설정하면 로그인에 필요(외부인 접속 차단) |
| `MARTON_VAPID_PUBLIC_KEY` / `MARTON_VAPID_PRIVATE_KEY` / `MARTON_VAPID_SUBJECT` | 권장 | 푸시 알림 키. `npx web-push generate-vapid-keys`로 생성해 고정 |
| `GEMINI_API_KEY` | 선택 | 사진 AI, AI 위치 답변, 음성 해석 보완, 손실 분석 AI |
| `MARTON_INTEGRATION_KEY` | 선택 | 센서·CCTV 경보 웹훅 인증 키 |
| `MARTON_DATA_FILE` | 선택 | 데이터 파일 경로 (기본 `data/marton-db.json`). 매일 백업 권장 |

> 정적 호스팅(Cloudflare assets)만으로는 동작하지 않습니다. 실시간 알림·저장을 위해 Express 서버가 필요합니다.
> 실제 배포 절차(Render 원클릭, Docker, 직원 설치, 플레이스토어)는 [marton-deploy.md](marton-deploy.md)를 따르세요.

## 4. 첫날 세팅 (30분)

1. 점장이 `https://<서버>/marton/` 접속 → 점장/부점장 로그인(PIN)
2. 조회실에 매장 접속 코드와 QR(접속 주소) 게시
3. 직원별: 접속 → 홈 화면에 추가 → 사번·이름·부서·담당 업무 로그인 → **푸시 알림 켜기** → 설정에서 **푸시 테스트**
4. 보안(MS) 담당 휴대폰에서 점장이 **보안 > 분석 > 테스트 센서 경보**를 보내 사이렌 확인
5. 안드로이드 현장 단말은 Chrome 배터리 최적화 해제(알림 지연 방지)

## 5. 역할별 사용법

**전 직원**
- 요청: 🎤 버튼으로 "수산에 고객응대 요청, 고객센터 앞" → 확인 → 보내기 (또는 요청 탭의 원터치 버튼)
- 받은 요청: 확인했어요 → 처리 시작 → 처리 완료 (단계마다 이름·시각 기록)
- 상품 찾기·촬영 AI: 위치 안내, 가격표 대조, 행사 전단 등록, 바코드 조회
- 보안 신고: 상황·위치·시간·상품만 기록. **직접 제지·추궁 금지**
- 퇴근: 설정 → 퇴근 · 로그아웃 → 인수인계 남기기

**보안(MS)**
- 진행 중 신고·센서 경보 사이렌 → 확인 → 현장 대응 → 종결(결과·손실 수량)
- 보안 > 순찰: 오늘 추천 시간대·구역 순찰 후 "순찰 완료"

**점장/부점장**
- 관리 탭: 미처리·긴급, 부서별 확인/완료 속도, 공지(전체·부서·긴급), 인수인계 확인 현황
- 보안 > 분석: 손실 지표, 구역·시간대·상품 분석, 예방 조치 추천, 주간 리포트(월 08시 자동) 복사·인쇄

## 6. 시범운영 계획 (4주)

| 주차 | 범위 | 목표 |
| --- | --- | --- |
| 0주 | 도입 전 1주 기준치 측정 (아래 지표를 수기로) | 비교 기준 확보 |
| 1주 | 고객센터 ↔ 수산·축산 업무요청만 | 알림 수신·응답 습관화 |
| 2주 | 전 부서 요청 + 상품 찾기 + 인수인계 | 사용률 확대 |
| 3~4주 | 보안 신고·순찰·주간 리포트 | 손실 데이터 축적, 첫 패턴 분석 |

## 7. 효과 측정 지표

| 지표 | 어디서 | 목표 예시 |
| --- | --- | --- |
| 요청 → 확인 평균 시간 | 관리 탭 KPI·부서별 처리속도 | 도입 전 대비 50% 단축 |
| 요청 → 완료 평균 시간 | 관리 탭 부서별 처리속도 | 단축 |
| 미처리로 남은 요청 수 | 관리 탭 미처리 | 매일 마감 시 0건 |
| 보안 신고 → 확인 평균 시간 | 보안 > 분석 평균 확인 | 3분 이내 |
| 추정 손실액 | 주간 리포트 | 4주 추세 감소 |
| 오인 신고 비율 | 보안 > 분석 | 40% 이하 (높으면 신고 기준 재교육) |
| 순찰 완료 횟수 | 주간 리포트 | 추천 슬롯 80% 이상 |
| 인수인계 확인률 | 관리 탭 인수인계 | 90% 이상 |

## 8. 개인정보·보안 체크리스트

- [ ] 보안 신고에 인상착의·신원 입력란 없음 (상황·위치·시간·상품만) — 교육 시 재강조
- [ ] 개인 휴대폰으로 고객 촬영 금지, 영상은 CCTV 시스템에서만 확인
- [ ] 업무요청 첨부 사진은 상품·가격표·바코드만 (카메라 화면에도 안내), 요청 완료 7일 후 자동 삭제
- [ ] 보안 신고 열람: 보안(MS)·관리자·신고자 본인, 진행 중일 때 해당 구역 부서만
- [ ] 종결 신고 180일, 순찰 기록 90일, 인수인계 30일 후 자동 삭제 — 회사 기준과 맞는지 확인
- [ ] 기기에 남는 데이터: 마지막 화면(보안 데이터 제외)·전송 대기 항목(로그아웃 시 삭제), 다음 로그인 편의용 사번·이름·부서·매장 코드
- [ ] 매장 접속 코드·관리자 PIN 정기 변경, 퇴사자 발생 시 변경
- [ ] CCTV·센서 연동 범위와 보관 기간은 개인정보보호법·사내 보안·노무 기준 검토 후 적용
- [ ] 데이터 파일 일일 백업, 서버 접근 권한 최소화

## 9. 알려진 한계

- 직원 인증은 사번·이름 + 매장 코드 수준입니다. 전사 확대 시 사내 SSO 연동이 필요합니다
- 데이터는 서버의 JSON 파일 1개에 저장됩니다(한 매장 규모용). 여러 매장으로 확대하면 데이터베이스로 이전이 필요합니다
- 아이폰은 홈 화면에 추가해야 푸시를 받고, Safari 음성 인식은 버전에 따라 안 될 수 있습니다(글 입력으로 대체)
- 상품 위치 데이터는 예시 16개입니다. 실제 상품·위치 등록이 필요합니다(엑셀 일괄 등록은 보류된 다음 단계)
